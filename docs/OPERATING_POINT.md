# Operating point

Generated by `python -m eval run eval/config/operating_point.yaml` from `eval/results/operating_point.json` (commit `090fe129b55f`). Do not edit by hand.

## How the thresholds were chosen

- Data: LFW open-set protocol (`eval/protocols/openset.py`), gallery of 1000 enrolled identities, one reference photo each.
- Each threshold is the score at which the target share of **non-mated** searches on the **tune** split raise an alert (FPIR). It is then applied unchanged to the **test** split (different people) to measure the miss rate (FNIR) and the real FPIR.
- Alert-load model: 200 sighting uploads/day x 4 faces/upload x FPIR = expected false alerts/day. The app raises at most one alert per upload, so this is an upper bound. Both numbers are parameters in `eval/config/operating_point.yaml`.

## Decision

- **MATCH_THRESHOLD = 0.312** (FPIR 1.00% on tune). On the test split it misses 0.60% of mated searches and alerts on 0.93% of non-mated ones, about 7.4 false alerts/day at the assumed load.
- **HIGH_CONF_THRESHOLD = 0.634** (FPIR 0.10% on tune), used only for the "High Similarity" label.
- Why FPIR 1%: every alert is reviewed by an officer, so a false alert costs a few minutes of review, while a missed match can cost a missing person. On LFW the 0.5% point is almost as good (FNIR 0.66% vs 0.60%, overlapping CIs) with fewer false alerts (2.9 vs 7.4/day), but real sightings have lower genuine scores than LFW, and the lower 1% threshold keeps more of them above the line. The 0.1% point would push FNIR to 33.17%; the 5% point adds 43 false alerts/day for 0.06% less FNIR.
- The 0.1% threshold (0.634) is set by the two highest non-mated scores among 1953 tune searches (likely look-alikes or LFW label errors), so it is fragile. It only controls the "High Similarity" label, not whether an alert is raised.
- The previous hand-picked MATCH_THRESHOLD (0.45) gives FNIR 1.91% and FPIR 0.10% on the same test split.

## Caveats

- LFW photos are mostly frontal, well lit celebrity photos. Real sightings (phone photos, CCTV, crowds) produce lower genuine scores, so the real FNIR will be higher than above; see the robustness results in `docs/EVALUATION.md`.
- FPIR depends on gallery size: more enrolled cases means more chances for a false rank-1 hit. Re-run this experiment when the number of active cases changes by an order of magnitude.
- The test split has 1944 non-mated searches, so FPIR = 0.1% rests on only a few errors and its CI is wide.
